# A manual install into a conda environment (RTX 3060 Laptop, the Coder IQ1_M)

This page records an install done by hand, without `setup.py`: the same steps setup does, with every dependency in
an active conda environment (`strata`) instead of `.venv` and a system CUDA toolkit. Use it when you want Strata in
your own conda environment, have no sudo, or already have the GGUF files.

## The PC

| | |
|---|---|
| GPU | NVIDIA GeForce RTX 3060 Laptop GPU, 12 GB VRAM, compute capability 8.6, driver 580.142 |
| CPU | AMD Ryzen 9 8945HX (AVX-512), 32 threads |
| RAM | 92 GB |
| OS | Ubuntu 24.04, Linux 6.8.0-136-generic, gcc 13.3.0 |
| Python | 3.14.7 in the conda environment `strata` (`~/miniconda3/envs/strata`) |
| Model | Qwen3.8-Flash-Next Coder, IQ1_M (2 shards, 58.4 GB), already downloaded |

## Why not setup.py

`./setup.sh` was tried first. Two things made the manual route the better one on this PC:

- **No ready-made engine.** Step 4 got HTTP 404 for the release download (v0.1.34, then the latest release), so the
  engine has to be compiled here.
- **The CUDA toolkit needs sudo.** setup installs `cuda-toolkit-13-0` through apt (`setup.py` `install_build_tools`),
  which asks for a password and stopped the run: `sudo: a terminal is required to read the password`.
- **Its Python packages go into `.venv`,** not into the conda environment. `setup.sh` creates `.venv` from whatever
  `python3` is first on PATH (here the conda one), with `include-system-site-packages = false`.

The CUDA toolkit from conda needs no sudo and lives in the environment, so everything below goes there. The `.venv`
setup made was deleted afterwards.

## 1. Copy the model files

The GGUF files came from a network share. A local copy on the SSD (`rsync`, 112 MB/s, 8 min 24 s for 59.3 GB):

```sh
rsync -a --info=progress2 "/mnt/evox2/Users/Wei Lu/Documents/Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF/" \
      ~/Documents/Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF/
```

The folder as published: the shards in `IQ1_M/`, the vision encoder one level up.

```
Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF/
  IQ1_M/Qwen3.8-Flash-Next-GSQ-RCO-IQ1_M-00001-of-00002.gguf   29.6 GB
```

All 7 file sizes were compared with the source after the copy: they match. (The `.done` files next to the shards
were written by the first `setup.py` run; they are harmless.)

## 2. Python packages

The same pinned packages setup installs, into the active environment:

```sh
conda activate strata
python -m pip install -r requirements.txt
```

This includes `cmake` 4.4.3 and `ninja` 1.13.2, used for the build.

## 3. The CUDA toolkit, from conda

```sh
conda install -n strata -c nvidia/label/cuda-13.0.3 -c nvidia cuda-toolkit=13.0.3
```

Installed: `cuda-toolkit` 13.0.3, `cuda-nvcc` 13.0.88, `cuda-cudart` 13.0.96, `libcublas` 13.1.1.3. `nvcc` is in
`$CONDA_PREFIX/bin`, the libraries in `$CONDA_PREFIX/lib`. CUDA 13.0 is what setup installs; an RTX 30 card (sm_86)
would also build with 12.x.

## 4. The engine

llama.cpp at the pinned commit (`3cf0325`) is in `third_party/llama.cpp` (the first `setup.py` run downloaded it;
`setup.py` `get_llama_cpp` shows the zip URL). The build uses setup's CMake flags, plus `CUDAToolkit_ROOT` so CMake
finds the conda toolkit:

```sh
cmake -G Ninja -S . -B build -DCMAKE_BUILD_TYPE=Release \
      -DSTRATA_ENABLE_CUDA=ON -DSTRATA_BUILD_TESTS=OFF -DCMAKE_CUDA_ARCHITECTURES=86 \
      -DCMAKE_CUDA_COMPILER=$CONDA_PREFIX/bin/nvcc -DCUDAToolkit_ROOT=$CONDA_PREFIX \
      -DSTRATA_GGML_DIR=$PWD/third_party/llama.cpp
cmake --build build --target strata -j 16
mkdir -p engine && cp build/strata engine/strata
```

It built on the first attempt (126 steps, system gcc 13.3.0 as the host compiler). `ldd engine/strata` shows
`libcudart.so.13`, `libcublas.so.13` and `libcublasLt.so.13` from `~/miniconda3/envs/strata/lib`.

`engine/BUILD.json` is written as setup writes it for a local build (`"source": "local"`, `"archs": [86]`, the
source fingerprint from `setup.source_hash`, `cuda_dirs` = the environment's `bin` and `lib`), so a later
`setup.py` sees the engine as already built.

## 5. The pack

The model data go to `../Strata-data`, setup's default data folder, so setup finds them too. The experts stay in the
GGUF and are read from it at start; the pack holds the index, the dense tensors and the tokenizer:

```sh
export STRATA_GGUF_PY=$PWD/third_party/llama.cpp/gguf-py
python tools/iq_pack.py \
  --gguf ~/Documents/Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF/IQ1_M/Qwen3.8-Flash-Next-GSQ-RCO-IQ1_M-00001-of-00002.gguf \
  --out ../Strata-data/packs/coder-iq1_m
```

Result: 1079 tensors, 302 served natively, arena 1.37 GiB; `tokenizer/` with a vocabulary of 248320. The low-RAM
`--experts-bin` file is not needed: IQ1_M uses ~23 GB of RAM and this PC has 92.

## 6. The MTP draft layer

The draft layer for speculative decoding comes from the original Qwen checkpoint (only its MTP tensors, 4.9 GB):

```sh
M=../Strata-data/mtp
python tools/mtp_fetch.py fetch --out $M
python tools/mtp_pack.py --src $M --experts q2_0 --out $M/mtp-q2_0.gguf
python tools/mtp_rt.py --gguf $M/mtp-q2_0.gguf --out $M/rt
cp data/draft_vocab.bin $M/rt/draft_vocab.bin     # setup's default subset (cjk)
```

## 7. The config and the start script

`strata-coder-iq1_m.json` carries the arguments setup chooses for this PC: 32K context (recommended for 12 GB
VRAM), 8-bit KV cache, no images, no KV streaming (it starts at 64K), no low-RAM mode. Shard 2 holds the
`per_layer_token_embd` table, so it is the `--ple-gguf`:

```json
{
 "exe": "/home/luwei/work/AI/Strata/engine/strata",
 "args": ["--pack", "/home/luwei/work/AI/Strata-data/packs/coder-iq1_m",
          "--native", "<GGUF folder>/IQ1_M/Qwen3.8-Flash-Next-GSQ-RCO-IQ1_M-00001-of-00002.gguf",
          "--ple-gguf", "<GGUF folder>/IQ1_M/Qwen3.8-Flash-Next-GSQ-RCO-IQ1_M-00002-of-00002.gguf",
          "--expert-profile", "/home/luwei/work/AI/Strata/data/expert-profile-coder.bin",
          "--expert-cache", "auto", "--prefill", "auto", "--spec", "4", "--spec-min-p", "0.5",
          "--mtp", "/home/luwei/work/AI/Strata-data/mtp/rt",
          "--max-context", "32768", "--kv", "int8"],
 "cwd": "/home/luwei/work/AI/Strata",
 "tokenizer": "/home/luwei/work/AI/Strata-data/packs/coder-iq1_m/tokenizer",
 "model_name": "qwen3.8-flash-next-coder-iq1_m",
 "log": "/home/luwei/work/AI/Strata/strata-coder-iq1_m.log",
 "lib_dirs": ["/home/luwei/miniconda3/envs/strata/bin", "/home/luwei/miniconda3/envs/strata/lib"],
 "port": 8080
}
```

`lib_dirs` is what makes the conda CUDA libraries work: the server puts them on the engine's `LD_LIBRARY_PATH`
(`serve/server.py`, `child_env`).

`run-coder-iq1_m.sh` starts the server with the environment's Python (not `.venv`):

```sh
#!/bin/sh
cd "/home/luwei/work/AI/Strata"
exec "/home/luwei/miniconda3/envs/strata/bin/python" "/home/luwei/work/AI/Strata/serve/server.py" --engine strata --config "/home/luwei/work/AI/Strata/strata-coder-iq1_m.json" --port 8080 --open
```

Start the model with `./run-coder-iq1_m.sh`, not `./setup.sh`: setup.sh would make a new `.venv`.

## First start and a test request

All steps done; the MTP layer is 4.9 GB of downloaded tensors, 848 MB as `mtp-q2_0.gguf` and 787 MB in `rt/`.

The first start (`python serve/server.py --engine strata --config strata-coder-iq1_m.json --port 8080`) answered
on `/v1/models` after 19 s:

- experts loaded into RAM: 23.42 GiB at 2.86 GiB/s
- GPU expert cache: 2666 experts, 5.11 GiB of VRAM; 11579 MiB of the 12288 MiB in use with the model loaded

One request, measured on this PC (RTX 3060 Laptop 12 GB, Ryzen 9 8945HX, 92 GB RAM; 32K context, 8-bit KV),
"Write a Python function that checks whether a number is prime. Code only.", `max_tokens` 600:

| | |
|---|---|
| prompt | 67 tokens in 1.31 s (51 tokens/s) |
| output | 245 tokens in 5.97 s (41.0 tokens/s) |
| MTP drafts | 164 of 197 accepted (83%) |
| expert cache hits | 64.6% |

The answer was a correct `is_prime` (trial division by odd numbers up to the square root). This is one short
request, not a benchmark: longer answers and longer contexts were not measured.
